# 产品范围与操作流程

## 1. 问题与目标

商家已有衣服、售价和库存，但需要反复将同一份资料填入平台的基本信息、属性、销售规格、尺寸、素材和物流区域。本系统先降低这部分人工有效操作时间，再减少资料准备成本。

目标指标是假设：资料已齐全的商品，人工填写及审核时间由约 20 分钟降至 1～3 分钟。不得将该数字当成当前性能承诺；拍照、补资料、等待平台处理分别统计。

首批用户是自己有真实店铺、熟悉上新流程的服装商家或运营人员。首个适配范围为单店铺、女装 T 恤叶子类目；“女装”不是足够具体的表单契约。连衣裙及其他女装类目在 T 恤草稿闭环通过后再增加。

## 2. 版本边界

当前验证版先完成真实 T 恤页面的单款填写、回读、保存草稿和重开。正式数据库、完整任务恢复和 10 款批量在真实草稿可行性成立后进入产品化阶段，避免先实现大量尚未被平台链路证明需要的基础设施。

| 能力 | v0.1 必做 | 后续 |
|---|---|---|
| 单款资料卡、店铺模板、SKU 表格粘贴 | 是 | 供应商数据导入、ERP 同步 |
| 本地真实图片、分类与顺序 | 是 | 自动抠图、排版、试穿图 |
| 标题手工编辑、结构化属性 | 是 | AI 标题、照片属性建议 |
| Playwright 填属性、SKU、尺寸、物流 | 是 | API 适配、更多类目 |
| 缺失项检查、回读差异、草稿保存与重开 | 是，草稿能力须验证 | 更高批量吞吐 |
| 人工发布、商品结果回收 | 是 | 经单独产品设计后的授权自动发布 |
| 持久化任务、暂停恢复、串行小批量 | 是，单款通过后启用批量 | 多执行器、多店铺 |
| 浏览器 AI | v0.1 不作为主流程依赖 | v0.1.1 受限异常辅助 |
| 视觉 OCR | 否 | v0.2 |
| AI 商品图、AI 视频 | 否 | v0.3、v0.4 |
| 多平台、库存实时同步、复杂 SaaS | 否 | v1.0 另行设计 |

商品详情不能因示意图未完整展示就跳过。目标类目真实发布要求的详情、服务、售后字段都属于 v0.1；可选营销素材可后置。

## 3. 信息分层与优先级

优先级：本款人工明确确认值 > 有来源且已确认的导入值 > 适用且有效的店铺配置 > AI 建议。不同事实来源冲突时生成问题，不静默覆盖。模板不得覆盖已有本款值。

| 数据层 | 示例 | 确认要求 |
|---|---|---|
| 店铺设置 | 店铺标识、运费模板、默认发货配置 | 首次选择并确认；运行时检查仍有效 |
| 类目模板 | 叶子类目、常用字段、尺码命名、详情布局 | 定义适用范围和版本；不能继承成衣尺寸、库存 |
| 本款事实 | 品牌、货号、成分、产地、实际颜色、尺寸 | 人工或可靠资料确认；必填未知值阻塞 |
| 交易配置 | 每 SKU 价格、库存、是否销售 | 用户确认；不能由模型推断 |
| AI 建议 | 标题、风格、图案、领型等 | 显示来源；低把握或冲突集中补充 |

成本为可选内部数据，不发送到发布表单，未填写不阻塞上新。

## 4. 单款用户流程

### 4.1 首次设置

1. 启动本地应用和可见浏览器，由用户登录商家后台。
2. 显示实际店铺身份，用户选择目标店铺；记录平台店铺 ID，不能仅按昵称识别。
3. 配置目标叶子类目、物流和其他真实必填默认项。
4. 实店模式选择已经验证可用的类目模板。开发模式使用明确标识的模拟模板，不要求连接店铺；模板未验证只阻塞实店执行，不阻塞资料界面和模拟流程开发。

### 4.2 准备本款

资料卡按“商品、图片、规格与库存、尺码、发布设置”组织。只显示当前任务需要的信息。

- 填货号及商品内部名称，选择品牌或平台允许的无品牌表达。
- 上传图片，标记所属货号、颜色、主图/详情/SKU 用途，拖动顺序。
- 输入实际销售颜色尺码组合；支持粘贴 CSV/表格和统一价后逐项覆盖。
- 导入实测尺寸或适穿建议，明确含义与单位；不要求二者同时提供，按类目规则判断。
- 编辑标题和属性，使用店铺物流默认方案或本款覆盖。
- 点击“检查资料”，生成阻塞项、待确认项与提醒；定位到具体字段修正。

不得生成不存在的销售组合。零库存的已存在 SKU 可保留；缺码组合不存在，应单独标识。

### 4.3 执行与审核

1. 校验通过，用户点击“自动填写”，锁定本次输入版本。
2. 执行器显示阶段进度，例如“正在核对 3 个销售规格”。用户可请求暂停。
3. 完成填写和回读对比，保存并重开草稿校验（平台能力通过验证时）。
4. 审核页展示目标店铺、标题、首图、规格逐行数据、尺寸、物流及差异；差异必须修正后才显示可交给人工发布。
5. 用户进入平台页面手动点击最终发布。应用中“已审核”仅是内部审核记录，不触发发布。
6. 系统通过页面或未来已授权官方 API 查询结果；未知状态保持“待确认结果”。
7. 已上架时展示实际取得的商品 ID、链接、确认时间；如果查询有登录依赖，同时注明验证范围。

## 5. 页面清单与验收行为

| 页面 | 必备内容 | 核心交互 |
|---|---|---|
| 商品列表 | 货号、首图、资料状态、最近刊登状态 | 新建、导入、筛选问题商品 |
| 商品资料卡 | 本款字段、来源、版本、缺失提示 | 保存、验证、确认 AI 建议 |
| 店铺与模板 | 店铺身份、类目、物流配置、验证时间 | 选择、更新、失效提示 |
| 批量检查页 | 逐款阻塞原因和可执行数量 | 仅入队通过项，失败项保留修改 |
| 任务中心 | 阶段、进度、重试原因、接管入口 | 暂停、恢复、取消、查看诊断 |
| 审核页 | SKU 明细、图片、尺寸、物流、字段差异 | 打开草稿、退回修改、标记内部已审核 |
| 结果页 | 草稿/处理中/未通过/已上架、ID、实际链接 | 刷新结果、导出 CSV |

普通商品界面不显示模型名称、DOM、属性 ID 等实现信息。诊断详情供维护者查看。

## 6. 批量与人工接管

- v0.1 先验证 10 款串行。100 款是长期容量目标，不是首版性能指标。
- 每款独立任务和状态；商品事实缺失只阻塞本款。店铺登录失效、身份不匹配则暂停该店铺队列。
- 有可靠草稿：逐款保存，集中审核时每次重新获取店铺执行锁并打开目标草稿。
- 无可靠草稿：使用“填写一款→人工审核发布→确认结果或人工结束→下一款”；不承诺后台一次填完多款。
- 人工接管时，自动执行器停止写入并保留当前页面；用户修改后先回读差异，不直接从旧断点继续。
- 取消只停止未来动作，不自动删除已建草稿、已传图片或已发布商品。界面说明已产生的结果。
- 商品执行中修改本地资料会生成新版本，原任务标记过期；需要显式选择以新版本重新准备，不能静默改正在执行的数据。

## 7. 图像与识别后续原则

照片输入可包含正面、背面、领口、袖口、吊牌、水洗标和细节。先做清晰度、重复、归属检查；多色商品必须有相应颜色资料，不能从黑色照片推断米白实际效果。

AI 生成属性保留证据；准确成分、尺寸、价格、库存、产地、品牌不从外观猜测。适穿建议与成衣测量分开。素材生成先处理压缩、裁剪与排版，再验证试穿图对衣服颜色、纹理、结构的保真度，生成结果需要审核。
