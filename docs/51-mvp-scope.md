# 收缩后的 MVP 开发与验收范围（2026-09-11）

状态：本文件是调整后的开发要求，不是完工声明。依据用户“需要一版 MVP，调整开发内容”的要求制定。发生范围冲突时，本文件优先于 00、01、06、21、49 中的历史计划；已有数据真实性、店铺校验和禁止未经授权发布的约束继续有效。

## 1. 交付目标

交付一个本机使用的“拼多多女装 T 恤单款填表助手”：商家输入真实资料和准备好的图片，系统完成支持范围内的重复填表、SKU 创建和上传，给出核对结果，商家在原页面补充例外项、检查并手动发布。

本版自动化终点为“填写完成，待人工检查”。完整使用流程的终点为商家手动发布，并从平台取得商品链接。自动发布、自动跟踪审核和自动回收新商品链接不作为本版验收条件。必须向用户明确这一区别，不能把草稿 ID、审核通过记录或预拼接地址称为可售链接。

## 2. 为什么之前迟迟没有收敛

此前清单把首版单款能力与稀疏 SKU、多尺寸模板、自动恢复、批量、发布结果跟踪等放在同一交付门槛。每补一个异常分支，又引入新的状态与回归场景。因此，剩余条目多并不意味着每个基础操作都没实现，也不代表必须重做架构。

本次采用固定商品范围、确定性执行、异常人工接管。已有代码保留；延期功能不再计入本版“尚未完成”。不能通过取消核对，把错误价格、错配库存或错误店铺当作成功。

## 3. 复杂度与取舍

| 能力 | 主要难点 | 本版决定 |
|---|---|---|
| 标题、固定属性、常规价格库存填写 | 页面定位、联动后回读 | 保留，复用现有执行器 |
| 标准颜色 × 尺码 SKU | 行定位与颜色、尺码、库存对应关系 | 保留完整组合；不同颜色使用相同尺码集合 |
| 新商品上传准备好的图片 | 上传完成等待、顺序和 SKU 绑定 | 保留；图片内容由人最终核实 |
| 已有图片补传、去重、平台转码后的内容识别 | 平台改写 URL、远端内容身份判断 | 延期；已有图的异常情况交给人处理 |
| 任意类目、资质和动态必填字段 | 类目/店铺条件不同，字段存在依赖 | 仅固定 T 恤模板；出现未支持必填项时提示人工补齐 |
| 稀疏 SKU、复杂促销、多种尺寸表 | 组合删除、模板切换、平台联动 | 延期；不把不存在的组合伪造成有货 SKU |
| 任何失败都能自动恢复 | 无法确定上一步是否生效、重复写入 | 延期；保留已实现的局部修正和草稿核查 |
| 3/10/50/100 款自动批量 | 队列、验证码、恢复、跨商品隔离 | 延期；用户逐款操作 |
| 自动发布及完整审核状态跟踪 | 外部审核状态和未知提交结果 | 延期；本版人工发布 |
| 照片识别、AI 文案、模特图、视频 | 真实性、生成一致性、成本和质量验收 | 全部延期 |
| 多平台、官方 API、SaaS | 权限、平台差异、账户与任务隔离 | 全部延期 |

## 4. 支持边界

- 一个已配置的拼多多店铺，本机单人使用；一次处理一款女装 T 恤。
- 标题、货号、品牌、面料成分、价格、库存、尺寸等由商家提供真实值，不用 AI 猜测。货号用于区分商品，不能因复用模板而沿用上一款身份。
- 仅支持现有执行器已验证的常规属性及枚举。特殊品牌资质、额外条件字段不承诺自动填写；预检或页面检查发现后明确交给人处理。
- 销售规格为完整颜色 × 尺码组合，每个组合有明确价格、库存和商家编码。不能自动填充缺失库存、不能默认所有组合均有货。
- 尺码表复用现有 cm 单值肩宽/胸围能力；其他测量列由商家在平台补充。本版不生成适穿身高体重建议。
- 商家准备真实主图、详情图和每种颜色的 SKU 图；本版不做抠图、换色、图片生成和视频生成。
- 发货时效、运费模板与服务设置使用一次确认的店铺配置；与当前页面不一致时提示处理，不擅自承诺服务。
- 登录、验证码、特殊资质、未覆盖控件由人操作。支持普通失败后在原页检查与人工接管，不承诺任意步骤自动续跑。

## 5. 用户流程与最小界面

### 第一次使用

启动本地工作台 → 登录商家浏览器 → 确认店铺 → 配置运费、发货与常用属性默认值。常用配置只需维护一次；默认值必须可见、可修改，不能隐含覆盖商品真实数据。

### 每次上新

1. 点击“新建商品”，从空白或常用模板开始。
2. 在真实工作台填写标题、货号、必要属性；录入颜色、尺码及每个 SKU 的价格库存；选择已准备好的图片。
3. 点击“检查资料”。缺值、无效文件、重复 SKU 或不支持的组合在打开填写任务前说明。
4. 点击“自动填写”，在已登录浏览器的目标页执行；使用现有支持的类目进入方式，需要人工进入 T 恤编辑页时直接给出引导。
5. 执行后展示“已核对字段、差异、待人工处理项”和当前商品/店铺。不能把还有差异的任务标为全部成功。
6. 商家在原页检查图片和例外项，必要时修改后再次核对。填写助手不点击发布。
7. 商家在拼多多手动发布、取得链接；如平台还在审核，按平台状态等待。下一款由用户主动新建。

录入界面必须对接真实 ProductPackage 和任务入口，不能只完善模拟表单。JSON 导入保留为高级入口，但不能要求普通用户手写完整 JSON。首版只做简单单款表单、小型 SKU 表格和本地图片选择，不做 Excel 映射向导、手机拍摄端或完整素材库。

图片核实至少展示主图顺序、各颜色对应的 SKU 图及详情图检查清单。远端 URL 改写后的“待人工核实”必须保留，不能为了报告变绿就视为内容验证成功。

## 6. 复用什么，实际还做什么

### 已有基础，直接复用

已有本地网页工作台、ProductPackage 运行时校验、店铺身份核对、Playwright 执行器、完整 SKU 矩阵、价格库存填写、三类图片上传、部分尺寸/属性/物流回读及本地任务记录。

已有受控测试商品真实填写、局部修正、保存草稿后重开回读证据。最新修正和保存结果见 `output/acceptance/2026-09-10/repair-and-save.json`：支持字段 34 项匹配，3 项素材待人工核实。该证据不代表全部女装、所有异常或商家全流程已经验收。

已实现的保存草稿、历史草稿定位、有限字段修正及在售链接读取作为辅助功能保留。本版不继续扩展其所有边界，也不要求用户必须先保存重开才能人工发布。

### 剩余开发只排三项

| 顺序 | 交付物 | 完成判据 |
|---|---|---|
| P1 | 真实单款录入表单与常用配置复用 | 用户无需编辑 JSON，能创建完整商品包并进入现有真实任务；新建商品不会覆盖上一款身份或资料 |
| P2 | 打通单款操作与人工接管 | 输入、目标页选择、填写、回读、差异提示在同一工作台完成；正常任务复用已登录浏览器；失败保留原页与结果，不自动重建/重传；不支持的必填项有明确说明 |
| P3 | 小范围真实验收与使用说明 | 下节规定的用例通过，记录实际耗时及限制；修复实际阻断上述范围的问题后交付 |

P2 优先修复实际妨碍此流程的缺陷。价格库存修正可先由人在平台完成再回读，不新增通用恢复引擎；现有草稿能力可复用，不再重构为分布式任务系统。

## 7. 验收条件

以三个在支持范围内的单款样本分别执行：单色多尺码、多色同尺码集合、各 SKU 价格库存不同。它们由用户逐款启动，不是自动批量验收，也不要求生产环境压测。

必须满足：

1. 从真实工作台录入资料到目标店铺填写完成，不依赖开发者手工改 JSON 或终端补跑业务步骤。
2. 标题、货号、颜色、尺码、SKU 对应关系、价格库存及已支持关键属性回读一致；未知或不一致不能自动显示“核对通过”。
3. 主图、SKU 图、详情图上传结果可供人工核实，错图、漏图有处理提示；人工检查后才由商家自行发布。
4. 至少验证一次字段差异：在原页人工修正后重新核对可得到更新结果，不需重新上传全部素材。
5. 正常使用保留登录会话；遇到验证或页面异常时明确停止、保留上下文、允许人工接管。不能因超时反复提交或新建商品。
6. 商品之间资料不串用，系统不会自动发布，不把草稿当作已上架。
7. 记录每款填表耗时、人工操作时间、人工补充项与失败原因。减少录入是评估目标；“1～3 分钟”仍是待验证指标，不能提前写成实测承诺。

测试商品禁止自动发布。真实手动发布验证只使用商家确认可售的商品；平台审核时间不计作自动填表耗时。若没有可售商品发布证据，只声明“填表助手已验收”，不宣称“新商品链接全流程已验收”。

## 8. 停止扩展的规则

- 不迁移前后端框架，不引入数据库、Redis、独立 worker 或 AI 浏览器代理。固定流程继续用现有 Playwright。
- 只修影响上述支持范围和验收用例的缺陷；其他发现记为延期项，不自动升级为本版阻断。
- 遇到支持范围外商品，清楚说明限制并交给人工，不静默猜值、不将用户拖入无限调试。
- 不用文档数量、测试数量或代码量汇报完成度；只报告 P1/P2/P3 的实物交付与验收证据。
- 本版通过后先交付使用、收集真实节省时间，再决定下一项是批量还是识图；不恢复原来所有功能同时推进。

## 9. 后续版本候选（本版不欠交）

稀疏 SKU、更多尺寸、已有素材复用、更强异常恢复、批量、自动回收发布结果、AI 识图/文案/图片/视频、多类目、多平台和 SaaS 均为后续独立立项。优先级由本版实际使用结果决定。
