# 真实单款网页工作台

## 启动

```sh
npm run workbench
```

打开 http://127.0.0.1:5173/ 。该命令同时启动本机任务服务（4318）和网页（5173），关闭终端会关闭本次服务。不要在已有服务运行时重复启动。

本轮已经启动这两个服务，可直接访问工作台。当前测试资料：

- 商品文件：examples/product-package-tshirt-live-test-v2.json
- 配置文件：.runtime/readback-logistics-context.json

上述是已有虚构测试输入，不用于正式销售。

## 使用流程

1. 选择商品JSON与核验配置JSON，点击“校验并载入”，核对页面显示的货号与目标店铺。
2. 点击“打开商家浏览器”。工作台使用独立的 .runtime/pdd-workbench-profile，首次需在新窗口登录；不会占用之前调试浏览器的资料目录。
3. 在商家浏览器中选择T恤类目并进入商品编辑页，工作台会自动列出该页面。多个编辑页时需明确选择。
4. 点击“填写并核对”“核对商品”或“保存草稿并重开”。这些按钮调用真实 runSingleWorkflow，不是模拟延时。
5. 查看进度、字段差异、未核实素材和剩余要求。报告可下载；历史任务可重新选择查看。

旧模拟界面单独放在 ?demo=1，默认打开真实工作台。

## 服务与持久化

- 仅监听127.0.0.1，校验Host和浏览器Origin；写入要求来自本地工作台的JSON请求，无跨域开放接口。
- 同时只允许一个任务或浏览器启动；执行中禁止替换商品配置。
- 用户选择的是服务所持有页面的ID，不能提交任意URL让服务导航。
- 已载入输入和配置在任务开始时快照。真实执行器再检查店铺、货号、类目和输入指纹。
- output/live-workbench 保存任务进度及结果，tasks子目录保留底层操作记录。服务重新启动后，旧running记录显示为“需检查”，不自动恢复写入。
- 新商品输入暂不跨服务重启自动恢复，需要重新导入；任务报告会恢复。
- “操作已结束”表示本次命令返回，不等于商品验证通过；草稿保存状态、检查结果及未完成要求另行显示。

## 后台启动与草稿恢复（2026-09-10）

推荐 `npm run workbench:start`，打开 http://127.0.0.1:5173/。关闭终端后服务继续运行；`npm run workbench:status` 查看进程，`npm run workbench:stop` 停止。日志位于 `.runtime/workbench-service/service.log`。服务重启自动恢复上次商品包和审核记录，不会自动重跑任务。

在编辑页选择“从草稿箱重开核对”，系统按商品ID查找编辑中草稿，校验草稿ID和店铺，再回读商品；不重复保存。重开的edit页面支持核对；确认来自草稿箱、状态为“编辑中”且编辑类型为“发布”的新商品草稿，也支持下面的局部修正和保存。

“人工审核记录”显示全部期望/实际字段，可勾选四类事实并记录通过，或填写原因退回。审核绑定当次报告，保留系统缺口。更换商品资料或后续写入后需要重新核对。

人工在商家页面完成发布后，保持或重新打开同商品编辑页，点击“读取发布结果”。系统只在找到对应ID、确认销售中且实际读取到匹配链接时显示商品链接；未找到会显示尚未确认在售。审核中/驳回等状态当前尚未精细区分。此按钮不会执行发布。

## 编辑页已关闭或保存结果未知

新版任务在执行前记录编辑页地址、商品版本和执行指纹。服务中断后，历史中的原任务保留“需检查”，不会自动继续写入。

1. 打开商家浏览器并登录；不用重新创建商品或找回旧标签页。
2. 载入原商品包及原店铺配置（重启通常会自动恢复）。
3. 在“近期任务”中点击原任务的“找回草稿并核对”。
4. 查看新生成的核查报告：草稿存在不等于最后一次保存成功；有差异时按差异修正，不能直接重跑原任务。

核查只从草稿箱读取并打开对应商品，不填写、不保存、不发布。商品版本或配置已变更时，先恢复原资料；原任务仍在运行时不能核查。旧版任务缺少编辑页地址或指纹时不提供此按钮。价格、库存、图片等步骤仍未支持自动续跑。

## 修正标题和服装属性差异

选择目标编辑页，点击“修正标题及属性差异”。系统重新读取整表，以当前载入商品包为准，只修正实际不一致的标题、品牌和已支持的独立服装属性。没有差异就不写入；图片待确认不会触发重新上传。商品货号不能通过此入口修改，价格、库存、面料组合和其他不支持的差异会继续列在报告中。

对edit页面，系统先从草稿箱核验同一店铺、商品ID、草稿ID及新商品草稿状态，再修改所选页面。已上架商品的修改草稿不在该入口范围内。局部修正后仍需查看完整报告，并点击“保存草稿并重开”确认保存结果。修正操作会使之前的审核报告失效。

真实验证：在测试草稿 `AUTO-ACCEPT-20260910-02` 中临时修改标题和袖长，工作台仅执行两个字段的修正；随后保存并从草稿箱重开成功。修正后及重开后均为34项匹配、0项差异、3类图片待确认。没有重新上传图片或执行发布。报告见 `output/acceptance/2026-09-10/repair-and-save.json`。
