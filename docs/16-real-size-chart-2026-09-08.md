# 真实尺码表填写与回读（2026-09-08）

## 交付范围

新增 `scripts/pdd-size-dom.mjs`、`scripts/pdd-size-adapter.mjs`、`scripts/pdd-fill-size.mjs`。执行范围限定新建女装 T 恤页，核对类目、货号和当前页面地址。当前只支持 `shoulderWidth`（肩宽）、`chestCircumference`（胸围），成衣尺寸、厘米、正数、最多一位小数，适配器保守限制不超过 300。此限制是本版本输入校验，不是已确认的平台上限。

本轮接入独立版本化填写计划，尚未接通统一 ProductPackage 尺寸编译或前端。输入值必须由商家提供，不能由 AI 根据人体推荐推断。

## 页面结构与执行过程

1. 在唯一 `newSpec` 表单区域中找尺寸名称完全一致的复选框。
2. 定位含 `beast-core-table-middle-header` 的唯一编辑表容器，并关联同容器中的 `beast-core-table-middle-body`。旁边的静态预览表不作为输入目标。
3. 读取表头名称和尺码行；按「尺码＋尺寸名称」关联输入框，兼容行列顺序变化。每次写入重新解析 DOM，不缓存行序号。
4. 预检所有行、列和控件，同时读取 SKU 快照，要求尺码表与 SKU 尺码集合一致。
5. 尺码表没有任何已有数值时允许补勾选缺少的尺寸列；不删除已有额外列，不改区间值模式。增加列前再次检查。
6. 使用 Playwright 原生 fill、Tab 触发页面事件，每格回读，末尾整张尺寸表再次核对。所有步骤检查 SKU 价格、库存、编码和启停值没有变化。
7. 失败记录已执行步骤并停止，输出 `needs_inspection`；不自动重试或回滚。

遇到区间值、只读或禁用输入框、多余列、重复或不一致尺码、多个编辑表、合并单元格均停止。已有同结构尺寸值会按显式计划更新；已有尺寸数据时不会扩展列。

## 使用

关闭占用相同 Chrome profile 的其他测试进程后，在项目根目录运行：

```bash
npm run pdd:fill-size -- examples/pdd-size-smoke.json
npm run pdd:fill-size -- examples/pdd-size-smoke.json --apply
npm run test:size
```

默认只读预检，报告列出需要补选的列；`--apply` 才执行。独立窗口中进入唯一的新建 T 恤编辑页，准备对应的规格矩阵及货号，按终端提示继续。默认 profile 为 `.runtime/pdd-inspection-profile`，可通过 `PDD_PROFILE_DIR` 覆盖。不得让两个浏览器进程同时使用该目录。

示例货号 `AUTO-MATRIX-20260908-02`，S：肩宽 37.5、胸围 86；M：肩宽 38.5、胸围 90。全部为虚构测试值，不能用于真实商品。与矩阵示例的货号不同，串联测试前需要统一货号及对应 SKU 编码。
