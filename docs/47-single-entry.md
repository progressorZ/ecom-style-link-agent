# 单款统一入口

## 启动当前测试商品

在项目目录运行：

```sh
npm run pdd:single -- examples/product-package-tshirt-live-test-v2.json .runtime/readback-logistics-context.json
```

这两个文件是本机已有的虚构测试商品和测试配置，不是正式待售商品资料。测试图片带“勿上架”，售价库存也不是实际经营数据。换成真实商品前，应提供真实输入及商家确认的配置。

程序打开独立Chrome窗口。首次需登录，登录资料保存到 `.runtime/pdd-single-profile`。在浏览器选择“女装/女士精品 > T恤 > T恤”进入编辑页，再回终端选择：

- **1 填写并核对**：依次填写基础信息、品牌属性、SKU、价格、尺码表、素材、物流并核对。适用于新商品空白素材区；已有图片不会盲目覆盖或重复追加。新建页面货号可以为空，已有非空货号必须与输入一致。
- **2 只核对**：对当前编辑页做独立读取，展示差异及未核实项。适用于检查已有草稿或人工修正后的页面。
- **3 保存草稿并重开**：先实时核对，通过已支持字段检查后点击一次保存；等待平台“保存成功!”提示，在新标签页重新打开并再次核对。素材、资质等未完成项仍标记为待审，不会变成发布许可。
- **0 退出**：关闭此次浏览器窗口。若仍有未保存编辑内容，应先完成需要的操作。

打开多个编辑页时，终端会列出地址，请选择要操作的页面。这里是终端菜单入口，尚未替换原有模拟网页工作台。

也可以先查看帮助：

```sh
npm run pdd:single -- --help
```

## 输入和输出

输入仍为统一商品包和核验配置。配置允许 shopBindings、freightProfiles、mediaReceipts，店铺绑定必填。命令执行前检查数据结构，任务运行时检查真实店铺和货号。

输出：

- `output/single-tasks/`：按操作、编辑页、店铺、执行指纹生成任务记录。保存输入计划、每步结果、保存意图、成功观察、重开回读或失败信息。
- `output/single-reports/`：每次操作的最终报告。
- 填写成功后，该进程自动携带本次素材上传回执供后续核对。重启进程时若需验证素材绑定，应使用任务中的 readback-context.json。

遇到异常，程序停止当前操作并保留窗口，先选2检查。相同任务记录已存在时不能盲目再次执行；目前还没有自动恢复或清理任务入口。不要删除任务记录来掩盖未知保存/上传结果。

## 当前边界

- 尚需人工登录、选择类目、进入编辑页；未实现从手机拍照直接启动。
- 服务承诺只核对，不会擅自修改。不同于输入时需人工处理。
- 草稿中已保存的折扣摘要目前可读取，自动修改该摘要的流程仍未支持；可人工修改再核对。
- 图片上传沿用已验证模块的空区域限制。已有素材的智能复用和平台改写地址后的内容确认未完成。
- 保存未发布草稿允许保留素材/资质待确认项；已知字段差异、不可读字段、错店或可见错误阻止保存。
- 只支持单款T恤，未实现批量调度、最终发布和商品链接回收；程序中没有发布分支。
- 此次统一入口的保存原语经隔离浏览器验证；46章有真实保存重开路径证据，但整个“从空白页填写到保存”的统一入口还未完成实店端到端验收。

## 开发改动及验证

新增 pdd-single-workflow.mjs 调度现有执行器与独立回读，新增 pdd-single.mjs 提供终端菜单。真实页面保存流程封装为 saveAndReopenDraft，保存/填写前落盘意图，失败保留任务，不自动重试。

验证覆盖：拒绝发布分支、保存门禁、未知结果记录、重复操作阻断、实际按钮只点击一次、保存后新页面读取、模拟持久化被篡改后拒绝通过。平台发布按钮从未被调用。
