# 真实基础填写与区域定位（2026-09-07）

## 本次交付

新增可运行的 `pdd:fill-basic` 命令及 `pdd-basic-adapter.mjs` 执行器，支持 **标题、整款货号** 两个字段。计划编译拒绝其他字段、重复键、空值及过长标题；运行时验证平台地址、新建页 type=add、T 恤类目、唯一字段容器及可编辑状态。

先预检所有请求字段，再逐个填写、blur 和重新定位回读，最后整体回读一遍。任何不匹配都停止并输出部分执行报告。代码不包含保存草稿、发布或任意按钮执行能力。`subset_verified` 只表示该字段子集一致，`fullProductVerified` 固定为 false，不代表整件商品可审核或发布。

这是一项独立的基础控件烟测，提前验证已定位控件的写入行为；不把它作为完整 R1 或 R2 完成。完整商品执行仍遵守全表定位、事实确认、SKU/素材/物流核对的前置条件。

## 运行方法

先关闭占用测试 profile 的其他自动化窗口。只读预检：

```bash
npm run pdd:fill-basic -- examples/pdd-basic-smoke.json
```

明确执行两个测试字段填写：

```bash
npm run pdd:fill-basic -- examples/pdd-basic-smoke.json --apply
```

命令显示完整字段计划；在独立 Chrome 窗口登录并进入指定店铺的新建 T 恤编辑页后，回终端按 Enter。只允许一个编辑页。运行结束留出人工检查时间，按 Enter 后关闭浏览器。

报告目录：`output/real-basic-fill/<时间>/report.json`。脚本失败不会自动重试或盲目回滚，需要检查是否部分填写。示例仅为未提交编辑页的测试标题和货号，不是真实商品事实，不可据此发布商品。

## SKU、尺码与区域定位

新增 `pdd-regions.mjs`，接入 `pdd:verify` 的 `regionInventory`。目前只读采集区域、按钮、文件输入数量、选项状态及表格结构，不执行上传。

现场发现并处理：

- 页面有两个 `id=sku`，必须同时限定 `beast-core-form-item` 容器，禁止只用 getElementById。
- 颜色表头实际为“颜色分类”。映射到内部颜色键后检查唯一表头。
- 颜色单元格跨 S/M 两行；`indexSkuRows` 展开 rowSpan，再以颜色和尺码组合键识别行。
- 价格库存输入按真实表头匹配，预览图列不会挤占规格编码列；重复规格、缺列、合并结构不完整、多输入格等情况停止。
- 尺码编辑区的表头和表体分属两个 table，另有预览表，不能把每个 table 当成独立完整尺码表。
- 运费模板区域在“展开修改”后可见；折叠时报告 not_visible，不猜测配置。

本次未提交的编辑页建立了白色 S/M 两个规格，并展开肩宽、胸围和物流区域。新版观察器识别了规格、主图、包装图、视频、发货时间和运费模板区域，并正确输出白色 S/M 行键。
