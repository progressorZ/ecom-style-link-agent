## 3. MVP 范围

MVP 只支持：

- 一个已授权拼多多店铺；
- 女装 T 恤叶子类目；
- 用户提供并确认标题、货号、属性、颜色、尺码、价格、库存、尺寸、图片和服务配置；
- Playwright 自动填写真实发布页；
- 保存草稿、重开、回读差异和人工审核；
- 单款稳定后串行处理最多 10 款。

MVP 不包含照片识别、文案自动生成、生成式商品图、视频、多平台、自动点击“提交并上架”和实时库存同步。

## 4. 实施顺序

### R1：真实只读定位验证

1. 把 `config/pdd/tshirt-v1.json` 编译成页面定位计划。
2. 在初始态和联动态逐字段验证唯一定位。
3. 对同名“请选择”“请输入”和“本地上传”使用字段区域限定。
4. 规格区按“颜色 + 尺码”识别行；不使用输入序号。
5. 输出定位通过、缺失、歧义及页面改版报告。

完成条件：所有计划内字段能唯一识别；任何歧义都停止，不写页面。

### R2：真实填写与回读

1. 使用专用测试货号和真实测试图片。
2. 按依赖顺序填写基础属性和动态子属性。
3. 建立颜色、尺码、尺码表和规格矩阵。
4. 填写每行拼单价、单买价、库存、规格编码、图片和状态。
5. 填写参考价、物流与服务。
6. 对照冻结输入逐字段回读；有差异时停止。

完成条件：至少 3 种代表性用例在保存前回读完全一致。

### R3：草稿可靠性

1. 只点击精确名称为“保存草稿”的按钮。
2. 记录保存前意图和保存后页面反馈。
3. 从草稿箱按可靠引用重开。
4. 再次核对标题、属性、图片、尺码表、规格、价格、库存和服务。
5. 测试保存超时和结果未知时的对账，避免重复草稿。

完成条件：草稿可以稳定保存、唯一查找并完整重开。若平台草稿不可靠，降级为逐款填写后立即人工审核。

### R4：小批量试点

先跑 3 款，再跑 10 款串行。每款独立状态；登录、店铺身份或页面级故障暂停整个店铺队列。记录自动执行时间、人工时间、差异和返工。

完成条件：关键交易字段零已知错误、无重复草稿、无自动发布，并证明人工有效操作时间显著下降。

### R5：产品化基础设施

真实草稿闭环成立后，再将现有 Vite 原型演进为正式应用服务，加入数据库 migration、持久任务、锁、恢复、素材存储和批量审核。PostgreSQL 与独立 worker 是目标架构，不是 R1～R3 的前置条件。

### R6：AI 与多平台

确定性流程稳定后，按实际异常样本评估浏览器 AI；照片识别、标题建议、素材生成和其他平台分别作为独立模块接入。AI 不决定价格、库存、尺寸和最终发布。

## 5. 技术决策

- 当前继续使用 React/Vite、Node.js 和 Playwright，避免在验证期迁移框架。
- 真实页面 Adapter 使用版本化配置、语义区域和业务行键。
- `ProductPackage → PlatformDraft → ObservedForm` 三层继续保留。
- 官方 API 权限继续后置；取得权限后与已验证浏览器路线比较覆盖和成本。
- 真实 profile、截图和 trace 只保存在本机运行目录，不提交源码。
- “提交并上架”保持代码级禁止；人工发布后才允许结果查询。
