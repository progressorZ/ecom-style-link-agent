# 统一 ProductPackage 编译

日期：2026-09-08。前一目标轮完成了发货时效代码和实测，属于有实质进展。本轮继续解决独立 JSON 无法统一驱动的问题，不涉及商品发布。

## 已实现

`scripts/pdd-package-plan.mjs` 从统一商品输入生成 7 个可交给既有适配器的原始子计划：基础信息、矩阵与 SKU、尺寸、轮播图、SKU 图、详情图、发货时效。注意各适配器的“编译结果”与“可执行输入”不总相同，输出 steps.input 保持原始输入契约，避免误把内部编译对象传回执行函数。

- 通过 variantId 关联报价，sizeKey 关联尺码，imageId 关联素材。
- 一个颜色键只能对应一个颜色名，尺码键与名称同样要求一致。
- SKU 素材的 colorKey 必须与规格一致；所有素材须 approved，顺序必须明确且同角色不重复。
- 全部选中尺码、实际规格尺码、尺寸表行必须一致；尺寸列与每行单元格集合一致。
- 当前只接受已经实现的 T 恤完整矩阵、中国码、一个成衣尺寸表和 24/48 小时承诺。
- 先深拷贝输入，输出源资料及全部嵌套子计划递归冻结。
- 使用按对象键排序的规范序列生成 SHA-256 sourceHash；数组顺序保留，输入字段变化会改变指纹。

指纹针对商品 JSON，不证明磁盘素材内容已固定；素材字节哈希和完整解码仍由执行前素材预检负责。编译器复用各模块业务校验并补跨实体关系校验，尚未接完整 JSON Schema 验证器，因此不能将编译成功等同于全部 schema 字段已严格验证。

## 使用

```bash
npm run pdd:compile-package -- examples/product-package-tshirt.json output/package-plan/tshirt.json
npm run test:package
```

此命令不启动浏览器、不保存草稿。新增示例使用虚构 T 恤数据，保留未确认 evidence，不能用于真实销售。历史连衣裙示例不改写，传入 T 恤编译器会被拒绝。
