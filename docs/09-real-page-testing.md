# 真实拼多多页面测试手册

## 1. 测试层级

本手册对应 [当前实施方案](00-current-plan.md) 的 R1～R3。双状态只读采集已经完成，后续采集只在页面改版、定位失败或需要补充下拉选项证据时进行。

真实页面测试分三层推进，每层通过后才进入下一层：

1. **只读勘察**：登录、进入目标类目、采集可见控件和截图，不写字段。
2. **草稿填写**：只使用专门测试商品，按 ProductPackage 填写并逐字段回读，只点击“保存草稿”。
3. **重开核对**：从草稿箱重新打开，以颜色和尺码组合键核对属性、规格、图片、价格、库存、服务和尺码表。

“提交并上架”不属于 v0.1 自动化测试。真实发布由人工审核后自行操作，系统随后读取结果。

## 2. 首次只读勘察

在项目目录执行：

```bash
npm install
npm run pdd:inspect -- 'https://mms.pinduoduo.com/'
```

命令会打开一个独立 Chrome 窗口，并把登录状态保存在 `.runtime/pdd-inspection-profile`。在这个窗口手工登录，进入目标“发布新商品”页面，然后回终端按 Enter。脚本只采集：

- 当前页面路径，不保存查询参数；
- 可见标题、标签、按钮以及输入控件的结构信息；
- 当前页面全页截图。

结果保存在 `output/real-discovery/<时间>/`。`controls.json` 不记录输入值、Cookie、localStorage 或完整 HTML；`locator-audit.json` 记录标签与最近输入控件的 DOM 关联候选。截图可能包含店铺名称，应只保存在本机开发环境。

采集完成后运行：

```bash
npm run pdd:analyze
```

分析器会读取最新采集，生成 `analysis.json`，报告字段覆盖、重复占位符风险和是否具备稳定定位器实现所需的数据。

普通 Chrome 已打开的页面不能被这个命令直接接管，因为它不是由 Playwright 启动的调试会话。直接在命令打开的独立窗口登录即可，后续运行会复用该独立 profile。

## 3. 运行只读定位验证

空白页面运行：

```bash
npm run pdd:verify -- initial
```

填写父属性并生成尺码表、规格矩阵后运行：

```bash
npm run pdd:verify -- linked
```

进入对应页面状态后回终端按 Enter。验证器逐项报告 `unique`、`missing_label`、`ambiguous_label`、`missing_control` 或 `ambiguous_control`，结果写入 `output/real-locator-verification/<时间>/report.json`。基础字段还需符合控件类型（包含真实 Beast 自定义下拉框结构）、placeholder、启用状态及多选标识，全部满足且“保存草稿”按钮恰好一个时仅标记 basicFieldsReady。类目、SKU 矩阵、尺码联动、素材及物流仍列为 unverifiedSections；完整 ready 保持 false，退出码为 2，不能据此进入真实填写。验证器即使检测到“提交并上架”也只记录门禁目标，不会点击任何按钮。

## 4. 草稿填写测试数据

准备专用测试货号，例如 `AUTO-TEST-001`，使用能够明确识别的测试图片和少量规格：

| 颜色 | 尺码 | 规格编码 | 库存 | 拼单价 | 单买价 | 状态 |
|---|---|---|---:|---:|---:|---|
| 白色 | S | AUTO-TEST-001-WHT-S | 1 | 1000.00 | 1001.00 | 启用 |
| 白色 | M | AUTO-TEST-001-WHT-M | 2 | 1000.00 | 1001.00 | 启用 |
| 白色 | L | AUTO-TEST-001-WHT-L | 0 | 1000.00 | 1001.00 | 停用测试 |

价格使用明显的测试值便于回读识别；不得保存不真实的库存到正式待售商品。填写流程必须停在保存草稿，测试前确认目标店铺和货号。

## 5. 必测联动

1. 选择叶子类目后，记录属性区重新加载及新增必填项。
2. 添加颜色并上传颜色图，确认该图是否传播到同色规格预览图。
3. 选择尺码模板、码制和 S/M/L，等待规格矩阵稳定后再填写规格行。
4. 取消一个尺码再重新勾选，确认已有规格值是否丢失或重排。
5. 修改一个父属性，观察下游属性是否出现、消失或清空。
6. 分别测试逐行填写、批量设置和 Excel 批量编辑，回读最终表格，不以按钮点击成功作为完成。
7. 勾选保存尺码表图片及同步详情，确认详情区出现对应内容。
8. 保存草稿后关闭页面，从草稿箱重新打开并再次比对。

## 6. 通过标准

- 预期规格集合与页面集合完全一致，无多余组合或缺失组合。
- 每行颜色、尺码、规格编码、拼单价、单买价、库存、预览图和状态一致。
- 商品编码没有写入规格编码，规格编码也没有覆盖整款商品编码。
- 所有重要属性、页面必填项、物流和服务承诺均有确定来源并可回读。
- 保存草稿有明确反馈，重开后关键字段仍完整。
- 自动化从未点击“提交并上架”。

完成只读勘察后，用生成的 `controls.json` 建立第一版 Pinduoduo Adapter 定位器。草稿写入工具要在这些证据确认后接入，避免凭截图猜测 DOM。
