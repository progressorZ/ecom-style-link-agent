# 开发计划与验收标准

本文是任务拆分。2026-09-07 起，实施顺序根据真实 T 恤页面双状态采集结果调整：模拟闭环保留为回归环境，立即验证真实页面定位、填写、回读和草稿可靠性；完整数据库、恢复系统和批量后台在真实草稿闭环成立后建设。官方 API 权限仍不作为浏览器路线前置条件。

## 1. 阶段与交付门槛

| 阶段 | 目标 | 输出 | 进入下一阶段的条件 |
|---|---|---|---|
| R0 基线与采集 | 建立领域、模拟闭环和真实字段证据 | React 原型、Schema、Mock API、模拟 E2E、双状态采集 | 已完成当前范围；保留回归 |
| R1 真实只读定位 | 验证 T 恤字段和规格行能稳定唯一定位 | 定位报告、歧义报告、页面版本证据 | 计划内字段均可唯一识别，零写入 |
| R2 真实单款填写 | 填写专用测试商品并完整回读 | PlatformDraft、ObservedForm、逐字段差异 | 3 个代表用例保存前完全一致 |
| R3 草稿与重开 | 验证保存副作用和持久化完整性 | 草稿引用、重开对比、未知结果处理 | 可稳定重开；否则明确逐款交互降级 |
| R4 小批量试点 | 先 3 款、再 10 款串行 | 时间、准确性、失败和返工报告 | 交易字段零已知错误、无重复、无自动发布 |
| R5 产品化基础 | 将验证脚本接入正式应用和持久任务 | PostgreSQL、worker、锁、恢复、批量审核 | 故障注入和恢复用例通过 |
| R6 AI 与扩展 | 按真实异常样本减少人工 | 受限诊断、识别、文案、素材及新平台 | AI 关闭不影响确定性主流程 |

R1～R3 证明单款真实链路可行，R4 证明节省时间的实际价值，R5 再完成可维护的 v0.1 产品化。AI 与素材能力不进入当前关键路径。

## 3. 测试分层

- 纯业务测试：金额解析、组合集合、尺寸单位、确认失效、引用一致性、规则编译。
- 页面夹具集成测试：模拟动态下拉、同名字段、虚拟表格、上传反馈、重排和未知弹窗，验证组件及回读；不将夹具通过当成真实平台通过。
- 任务故障测试：在外部副作用前后注入进程终止、超时、租约丢失，验证恢复不会重复创建。
- 真实店铺试点：只操作已授权的测试商品，默认停在发布前；真实发布由商家手动进行，用于验证结果回收。
- AI 评测：独立异常集与禁止动作集；浏览器操作边界由程序测试证明，不依赖提示词承诺。

## 4. 最低验收矩阵

| 用例 | 输入/故障 | 必须观察到的结果 |
|---|---|---|
| T01 正常单色 | 一个颜色、四个尺码 | 所有字段精确一致 |
| T02 稀疏多色 | 黑 S/M、米白 M | 仅三个有效销售组合 |
| T03 零库存 | 已存在 SKU 为 0 | 保留正确事实，按规则处理销售状态 |
| T04 不同价 | 不同 SKU 售价不同 | 无统一价误覆盖 |
| T05 多价格字段 | 页面有多个独立价格角色 | 缺少对应输入时阻塞，不猜值 |
| T06 表格重排/虚拟滚动 | 增删颜色导致行位置变化 | 仍按组合键全量核对 |
| T07 相近尺码 | XL、2XL、XXL | 按明确映射，重复等价键可检测 |
| T08 尺寸含义 | 成衣胸围与人体建议并存 | 不混表，不做隐式换算 |
| T09 图片串色 | 米白 SKU 误绑黑色图 | 预检阻塞，指出对应 SKU |
| T10 上传中断 | 部分文件已传、绑定未完成 | 查询已传结果，只补缺失绑定 |
| T11 动态属性 | 选材质后新增必填 | 已知值填入，未知值集中提示 |
| T12 草稿超时 | 点击保存后反馈丢失 | 进入对账，不新建重复草稿 |
| T13 草稿丢字段 | 重开后少图片/尺寸 | 不标 draft_ready，修复或降级 |
| T14 登录失效/错店铺 | 执行中失去会话或切换店铺 | 全店暂停，无后续写入 |
| T15 人工修改 | 接管后改价格 | 显示差异，旧审核失效 |
| T16 进程崩溃 | intent 后 observation 前终止 | 新 worker 核实旧进程停止并对账 |
| T17 双击执行 | 同 key 重复请求/不同 key 同刊登 | 返回原任务或冲突，无并发重复 |
| T18 批量混合 | 10 款中 2 款缺资料 | 明确 8 个接受、2 个阻塞；不静默丢项 |
| T19 未知发布结果 | 人工说已提交但无平台证据 | outcome_unknown，无伪造链接 |
| T20 提交未上架 | 平台处理中/未通过 | 正确状态和原因，不显示可售 |
| T21 发布门禁 | 出现“保存并上线” | 不被任何草稿/AI 流程点击 |
| T22 AI 注入 | 页面要求忽略规则、改库存或发布 | 策略拒绝，无外部副作用 |
| T23 库存过期 | 排队或恢复超过确认 TTL | 要求重新确认，原快照作废 |
| T24 用户取消 | 上传后/保存后取消 | 停止后续动作，保留副作用摘要 |

## 5. 试点指标和口径

R4 先验证 3 款代表性商品，再扩到 10 款，包含单色、多色、缺码、不同价、不同图片数和尺寸格式。10 款通过后可扩大到 20 款以获得更稳定的指标；任何小样本结果都不外推到全部女装或其他店铺。

| 指标 | 建议 v0.1 门槛 | 统计口径 |
|---|---|---|
| 关键交易数据准确 | 0 个已知价格/库存/SKU 错误 | 对最终草稿逐行比对；不能只比总数 |
| 首次填表通过 | ≥90% | 无人工修复的 review_ready 款数 / 已满足输入条件的执行款数；另报全部导入款完成率 |
| 人工有效操作时间 | 中位数目标 ≤3 分钟/款 | 数据已齐全后的输入、异常处理、审核相加；同时报告 P90 与最大值 |
| 重复创建 | 0 | 故障与重复请求用例中无意外重复商品/草稿 |
| 异常可定位 | 100% 有阶段与原因 | 所有失败/暂停都有商家可理解原因及必要证据 |
| 自动发布 | 0 次 | v0.1 任何运行模式均不触发最终发布 |
| 结果可追溯 | 100% 输出有状态来源 | 未知明确标未知，不为“链接齐全率”伪造结果 |

总耗时分为准备资料、队列等待、自动执行、人工处理、平台等待。另报拍照和供应商资料整理成本，防止只是把填平台的工作转移到填自己系统。

单款成本 = 模型调用 + 素材处理 + 运行资源 + 人工返工 + 维护分摊。ROI 使用实测节省人工时间乘商家人工成本，再减运行和维护成本；不提前承诺收益。

## 6. 风险与降级

| 风险 | 首版应对 | 扩展前条件 |
|---|---|---|
| 无官方 API 权限 | 已验证浏览器路线 | 有权限后比较真实接口覆盖，不只做字段名转换 |
| 草稿无法可靠保存 | 逐款交互审核 | 能重开并核对才启用集中草稿批量 |
| 页面改版 | 限定类目、夹具回归、诊断与接管 | 不承诺 AI 自动修好所有页面 |
| 图片生成改错衣服 | v0.1 用真实图片 | 专项保真评测与人工审核 |
| 库存来源滞后 | 确认时间与快照 | 多平台前建立库存分配/同步机制 |
| 平台限制自动化操作 | 暂停、核查可用授权能力 | 不以规避限制为技术方案 |

## 7. 完成定义

每个开发任务需有实现、相关测试、文档更新和明确的实际验证范围。R3 交付真实单款草稿闭环报告；R4 交付真实小批量报告；R5 再交付正式应用、环境配置示例、数据库 migration、备份恢复和持久任务故障报告。

当前立即验收真实 DOM 定位、平台动态字段、写入回读和草稿持久化。发布状态和实际链接只能在人工发布测试后验收；在此之前保持 `outcome_unknown`。
