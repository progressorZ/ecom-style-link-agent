# 拼多多浏览器执行、校验与恢复

## 1. 依据与边界

早期六张图片只作为业务示意。当前已经取得 T 恤真实页面四张截图、初始态 DOM 采集和联动态 DOM 采集，确认了字段覆盖、部分属性依赖、尺码表和规格矩阵。真实定位候选见 [`config/pdd/tshirt-v1.json`](../config/pdd/tshirt-v1.json)。

模拟页面闭环已经通过，当前按以下步骤实现真实 T 恤 Adapter。现有采集只证明可见结构，真实写入、下拉选项选择、保存和重开必须逐步验证；模拟页面定位器不复用为拼多多定位器。

## 2. 运行前准备

1. R1～R3 确认只有当前本地验证进程和用户共同操作专用浏览器 profile；R5 再由 worker 租约和店铺锁保证唯一写入者。
2. 读取实际平台店铺身份，与任务 shopId 匹配；验证登录和页面可用。
3. 加载冻结的测试输入、T 恤定位契约和 Adapter 版本；校验库存确认时间。
4. 所有素材导入受控目录并完成文件校验；提前准备符合约束的派生图。
5. 已有 draftId 时先打开核实；无外部引用但存在未确认创建动作时先对账，禁止直接新建。
6. v0.1 仅进入保存草稿或人工交接路径，任何“保存并上线”“提交并上架”都作为发布动作排除。

## 3. 步骤表

| StepKey | 输入 | 操作与完成条件 | 失败处理 |
|---|---|---|---|
| ensure_session | shopId、profileRef | 登录有效且身份精确匹配 | AUTH_REQUIRED / SHOP_MISMATCH，暂停店铺队列 |
| open_editor | draftRef 或新建意图 | 唯一目标编辑页可见，商品身份可核对 | 先对账，不盲目重建 |
| set_category | categoryBinding | 选择真实叶子类目，确认属性区域更新完毕 | 未知类目/清空已有字段则重新编译 |
| fill_basic | 标题、类型、内部映射字段 | 写入、触发必要 blur/change、回读 | 长度错误或多个候选输入则阻塞 |
| fill_attributes | 平台属性键与值 | 按依赖拓扑填写，直到无新增必填字段 | 不存在选项、未知新必填项转 needs_input |
| bind_main_detail | 排序素材引用 | 上传并绑定，确认缩略图、顺序、详情保存 | 断点恢复见素材流程 |
| build_variants | 实际颜色尺码集合 | 构建规格，消除不存在组合，回读全集 | 不支持稀疏组合则阻塞本款，不能改成假库存 |
| fill_offers | 每规格价格、库存、编码、图片 | 精确逐行填入并逐行比对 | 差异按组合键报告 |
| fill_size_chart | 已确认尺寸/建议 | 建列、录行、核对单位和范围 | 未知字段含义暂停 |
| fill_logistics_services | 店铺物流、本款覆盖、服务字段 | 检查模板有效，选择并回读所有必填项 | 不选列表第一项作为兜底 |
| verify_full_form | PlatformDraft | 核对全部区域及页面错误 | 不一致不进入 review_ready |
| save_draft | 已核对表单 | 明确保存反馈，取得引用并记录 | 超时进入 reconciling |
| reopen_verify | draftRef | 重开后再次核对，确认持久化完整 | 草稿丢字段则修正或回退交互模式 |
| handoff_review | 对比报告、目标页 | 展示审核记录，停止自动写入 | 人工修改后重新回读 |
| observe_outcome | 平台目标、人工发布线索 | 获取真实商品 ID、状态、链接及证据 | 未知保持 outcome_unknown |

## 4. 属性依赖处理

规则表字段包含 semanticKey、平台 fieldId（可得时）、label、controlType、requiredWhen、allowedValues、dependsOn、readbackStrategy。UI 路线没有可靠 fieldId 时使用验证过的语义键和页面组件定位，不能伪造属性 ID。

执行前确定类目。填写一个父属性后重新扫描相关子区域；新增必填值已存在于输入则填写，缺失则暂停收集问题。建议最多 5 轮依赖收敛，超过则报 DYNAMIC_RULE_UNRESOLVED；数字是工程保护阈值，可配置。

相同标签在基本属性和销售规格中可能各出现一次，必须按所属区域限定，不能对全页第一个匹配直接填写。

## 5. 控件定位约定

优先使用区域内的 label / role / accessible name，再使用明确文本和已验证稳定 DOM 结构。页面没有真实 label 时，使用字段容器内关系定位；CSS 并非禁用，但必须说明依据及页面夹具测试覆盖。

- 匹配 0 个或多个目标时失败，不用 `.first()` 掩盖歧义。
- 自定义下拉不假定是 HTML select；打开后只在当前弹层选择精确选项。
- 输入后等待明确保存/重算信号，并读取业务值；避免用固定 sleep 代替完成判断。
- 关键操作由页面组件封装，调用者传业务键，不传任意 XPath 或屏幕坐标。
- 页面上显示“可点击”只证明可交互，不证明业务填写成功。

定位和输入能力依据：[Playwright Locators](https://playwright.dev/docs/locators)、[Actions](https://playwright.dev/docs/input)。

## 6. SKU 专项算法

1. 用 `(colorKey,sizeKey)` 建 expected map，校验无重复，并保存展示名到平台值映射。
2. 按实际页面先建立颜色、尺码，再读取产生的全部规格。
3. 比较 actual set 与 expected set。删除/禁用额外组合前确认这是本次新建草稿中的生成项；不能误删既有商品规格。
4. 对每个 expected key 定位唯一行。行可跨页或虚拟滚动，维护 visited set；不能只读取 DOM 当前渲染行数。
5. 批量设置统一价仅在所有目标行同价且控件范围可验证时使用，之后仍逐行验证。
6. 写入价格角色、库存、编码、图片，触发页面重算；若重排，重新按 key 定位。
7. 逐行比对完成后，检查全集、总行数、编码唯一性、图片颜色、价格范围和库存总量。

照片 1 按 S/M/L 展示的简化行，不足以证明真实页面没有颜色维度。内部主键始终包含所有实际销售维度。

## 7. 图片上传与绑定

素材状态：`local_validated → uploading → uploaded → binding → bound_verified`，每一步可有 failed/unknown。外部图片空间存在不代表已绑定商品。

具体流程：打开目标用途上传入口 → 监听 file chooser 或使用 file input → 选择受控本地文件 → 等待每文件成功反馈 → 记录可取得的媒体引用 → 精确勾选本次商品素材 → 确认 → 回到编辑器核对。

如果平台无法取得稳定媒体 ID，记录可验证的文件名、缩略图、时间与页面引用等证据；不足以唯一确认时人工接管，不宣称严格去重。上传重试前查询已有结果，避免不断重复上传。

同一文件可复用于同颜色多个尺码的 SKU 图；主图和详情仍要分别绑定。缩略图数量正确但顺序错误同样判失败。平台压缩后的图片不要求字节 hash 相同，应验证关联的媒体对象或可证明的图像对应关系。

## 8. 尺码表专项

1. 确认平台组件当前解释的是成衣测量还是适穿建议。
2. 选择列，显式处理 cm/kg 等单位；不从字段位置推断含义。
3. 按 sizeKey 映射平台展示尺码，创建目标行。
4. 输入单值或范围；范围两端不合并成无法解析的自由文本，除非平台仅支持该形式且已验证。
5. 回读列标签、单位、全部行值；检查覆盖实际销售尺码。
6. 不点击平台“AI 尺码推荐”作为事实补全；缺实测信息时需要用户提供。

## 9. 重试与故障分类

以下为初始运行配置，可按真实数据调整，不是平台限制。

| 故障 | 自动处理 | 上限/后续 |
|---|---|---|
| 读取或定位临时超时 | 重新观察、等待目标状态 | 2 次，仍失败转诊断 |
| 网络/上传失败，明确未成功 | 指数退避 + jitter，先检查已上传结果 | 最多 3 次 |
| 保存草稿超时 | 进入 reconciling，按外部引用核对 | 未确定之前不再点保存/新建 |
| 价格/库存回读不同 | 重新定位该组合并在安全状态修正 | 1 次，仍不同人工接管 |
| 必填值缺失、选项不匹配 | 无自动猜值 | waiting_user |
| 登录失效、验证码、店铺不符 | 停止店铺队列 | 用户完成后重新核对身份 |
| 平台繁忙或操作受限 | 停止重复写入，按提示等待/接管 | 不通过多账号/多浏览器绕过 |
| 页面未知弹窗 | AI 诊断可选，默认暂停 | 不默认确认或关闭 |
| 浏览器崩溃、worker 重启 | 确认旧拥有者停止，加载 checkpoint，对账 | 不从第 1 步直接重放 |

默认定位等待可设 15 秒、导航 30 秒、上传每文件 120 秒，均需配置。worker 等待期间仍心跳并可报告状态。暂停请求在安全边界生效。

## 10. 人工接管、草稿与结果

保存草稿成功必须有明确反馈，并能重新打开目标草稿验证关键字段。仅截图显示“保存草稿”按钮，不能证明可用。

无草稿能力时，保留当前编辑页并进入 interactive review；期间不允许同店铺后台执行下一款。人工结束或保存结果确认后释放写权限。

人工发布后可采用用户触发“检查发布结果”，或在该审核会话有限轮询。建议初始间隔 10 秒、持续 2 分钟，随后提示等待并提供再次检查；平台审核可能更长，超时不视为失败。监测结束释放适用锁，后续查询与其他同店铺操作协调。

结果证据至少包括来源页面、观察时间、商品 ID、平台状态；取得实际 URL 后记录。禁止仅凭成功 toast、内部 job succeeded、猜测链接模板标 live。

## 11. 证据与复现

失败保存脱敏截图、当前 URL（必要参数脱敏）、组件观察、最近步骤及预期/实际差异。敏感 trace 放受限目录，不默认上传模型。Playwright 提供 trace 排查能力，接入时按实际 worker 运行方式验证启停与存储：[Trace viewer](https://playwright.dev/docs/trace-viewer)。

每次修复定位器增加对应脱敏页面夹具或异常回归，避免把某次模型定位成功直接永久加入全局规则。
