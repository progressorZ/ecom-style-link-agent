# 拼多多板鞋类目取证与共用设计

## 当前证据

- 用户已在商家后台打开目标编辑页，URL 中类目 ID 为 `201517965903`，页面类目路径为“童鞋/婴儿鞋/亲子鞋 > 板鞋 > 板鞋”。
- 工作台不会接管用户普通浏览器中已经打开的标签页。项目已提供独立的专用商家浏览器和只读选项采集器；用户在该浏览器登录并进入目标页后，可一次采集已登记的下拉选项。尚未成功采集或人工观察的选项、必填性和联动规则仍保持未验证。
- 已从脱敏截图观察到基础属性、素材区、颜色分类、童鞋尺码、尺码表、价格库存和基础服务的页面原文，记录在 `config/pdd/board-shoes-v1.json`。截图观察只把字段标为 `observed`，不代表已经完成写入与回读验证，`executionEnabled` 继续为 `false`。
- 颜色分类支持标准颜色多选、颜色备注和每色规格图。童鞋尺码包含欧码、英码、通用和自定义入口；欧码已观察16至42及半码，英码已观察0至13及半码。
- 平台推荐尺码模板会生成尺码表，已观察脚长(mm)、脚宽(mm)、区间值、排序、保存尺码表图片及同步添加到商品详情。生成后的价格库存表按颜色分类×童鞋尺码展开，每行有库存、双价格、预览图、规格编码和启停状态。

## 与女装 T 恤共用

商品货号、标题、品牌、颜色与尺码两个规格维度、规格编码、双价格、库存、启停状态、主图、详情图、颜色规格图、发货时效、运费配置、人工审核和任务报告都应由平台核心组件提供。类目 Adapter 只声明差异，不再复制整套页面和任务系统。

目前已抽出的共用层包括：

- `config/category-profiles.json`：类目事实字段、规格维度、尺码模式与默认值。
- `schemas/category-profile.schema.json`：社区新增 Profile 时的机器校验合同。
- `src/listing-draft.ts`：跨类目的商品草稿、规格矩阵、校验与安全导出。
- `scripts/category-profile-compiler.mjs`：Adapter 可复用的非 UI 编译入口。
- `src/CategoryWorkbench.tsx`：由 Profile 驱动的第二类目工作台，用来验证 UI 不再绑定 T 恤字段。
- `src/local-assets.ts`：类目无关的 JPG/PNG 本机素材上传。
- `src/tabular-input.ts` 与 `src/variant-bulk.ts`：共用表格解析和按两维规格匹配的价格库存导入。

板鞋工作台现在还提供完整初始示例和多个本机商品模板。套用模板会生成新货号并重建 SKU，价格、库存和素材保持可见，供用户逐项复核。示例仅用于理解字段结构，不是可销售的商品事实。

板鞋工作台还提供只读的“自动采集下拉选项”：打开专用商家浏览器、登录并进入类目 ID `201517965903` 的发布页后，一次点击即可依次展开已登记的属性控件并下载 JSON 报告。采集过程不选择选项、不填写字段、不保存草稿、不发布商品；依赖其他属性才启用或无法唯一定位的控件会标记为 `disabled` 或 `unreadable`，不会猜测。当前报告用于继续完善页面合同，还不会自动改写 Profile 或把未审核选项直接加入用户表单。

源码开发者也可以运行 `npm run pdd:inspect -- "目标编辑页 URL"`。结果保存在 `output/real-discovery/<时间>/`，其中 `select-options.json` 是自动读取的选项报告。

现有 T 恤执行脚本仍作为已验证实现保留。待板鞋页面合同完成后，再把两者接入同一 `preflight → fill → readback` 运行器，避免为追求形式统一而破坏已工作的 T 恤 MVP。

## 板鞋差异

- 服装属性替换为鞋面材质、鞋底材质、适用性别、闭合方式、鞋帮高度、适用年龄段、季节、工艺及生产信息等童鞋事实。
- 第二规格维度是童鞋尺码；支持欧码、英码、通用、半码和自定义童鞋尺码，仍需验证真实写入后的排序与回读。
- T 恤成衣尺寸表不能复用。童鞋使用脚长/脚宽毫米尺码表；本地录入、区间值和同步意图已经独立建模，平台模板选择、写入和回读仍需板鞋专用执行模块。
- 类目属性间可能存在依赖，例如鞋面材质影响后续选项；必须记录控件出现顺序和清空行为。

## 不依赖真实页面的本地能力

以下能力可以在自动填表保持关闭的情况下开发和测试：

- 基础资料和童鞋属性录入，以及完整初始示例。
- 欧码、英码、通用码和自定义鞋码；颜色×鞋码矩阵与 SKU 编码。
- 拼单价、单买价、库存、参考价、满件折扣及整表导入和粘贴。
- 脚长/脚宽毫米尺码表、单值或上下限区间，以及同步至详情的刊登意图。
- 主图、辅助图、包装标签图、详情图和每色规格图的本机素材清单。
- 发货时效、固定服务事实、可选承诺和偏远地区模板名称。
- 多个商品模板、旧草稿迁移、业务资料备份与不可执行的 JSON 草稿导出。

这些本地能力均标为 `experimental`，只说明数据录入、校验和导出可运行，不代表对应字段已经能写入平台。

4. **待完成**：实现板鞋专用页面执行器，并在真实草稿执行填写、保存、重开和独立回读；不点击最终发布。

属性选项、确定性选择器、保存平台草稿、重开与独立回读属于真实页面验证范围。完成前 `config/pdd/board-shoes-v1.json` 的 `executionEnabled` 必须保持 `false`，且最终发布始终由商家操作。

## 数据与证据边界

采集报告、任务报告和商品草稿可能包含商品原文、平台页面地址或本机素材路径。提交 Issue 或 Pull Request 前必须脱敏，不要上传 `data` 目录、浏览器登录资料、店铺身份或真实用户图片。业务资料备份不包含专用浏览器登录状态，完整边界见 [`PRIVACY.md`](../PRIVACY.md) 和 [`SECURITY.md`](../SECURITY.md)。
