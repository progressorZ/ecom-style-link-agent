# 拼多多板鞋类目取证与共用设计

## 当前证据

- 用户已在商家后台打开目标编辑页，URL 中类目 ID 为 `201517965903`。
- 浏览器安全策略阻止了自动读取商家编辑页，因此没有把未观察到的标签、必填性或下拉选项写成已验证规则。
- 当前 Profile 中的鞋面材质、鞋底材质、闭合方式、鞋头款式等是内部商品事实字段，全部标记为 `unverified`，不能直接视为拼多多原文字段。

## 与女装 T 恤共用

商品货号、标题、品牌、颜色与尺码两个规格维度、规格编码、双价格、库存、启停状态、主图、详情图、颜色规格图、发货时效、运费配置、人工审核和任务报告都应由平台核心组件提供。类目 Adapter 只声明差异，不再复制整套页面和任务系统。

目前已抽出的共用层包括：

- `config/category-profiles.json`：类目事实字段、规格维度、尺码模式与默认值。
- `schemas/category-profile.schema.json`：社区新增 Profile 时的机器校验合同。
- `src/listing-draft.ts`：跨类目的商品草稿、规格矩阵、校验与安全导出。
- `scripts/category-profile-compiler.mjs`：Adapter 可复用的非 UI 编译入口。
- `src/CategoryWorkbench.tsx`：由 Profile 驱动的第二类目工作台，用来验证 UI 不再绑定 T 恤字段。

现有 T 恤执行脚本仍作为已验证实现保留。待板鞋页面合同完成后，再把两者接入同一 `preflight → fill → readback` 运行器，避免为追求形式统一而破坏已工作的 T 恤 MVP。

## 板鞋差异

- 服装属性替换为鞋面、鞋底、闭合方式、鞋头、鞋帮、鞋跟、适用人群等鞋类事实。
- 第二规格维度是鞋码；需确认平台鞋码体系、半码、尺码排序和自定义鞋码规则。
- T 恤成衣尺寸表不能复用。板鞋可能需要脚长/内长/鞋码建议，具体字段和同步方式必须按页面核对。
- 类目属性间可能存在依赖，例如鞋面材质影响后续选项；必须记录控件出现顺序和清空行为。

## 启用自动填表前必须完成

1. 提供脱敏全页截图，覆盖基本信息、全部属性、规格区、价格库存、素材、物流和服务。
2. 逐项记录标签原文、必填状态、控件类型、选项值及依赖关系。
3. 创建本地 HTML fixture，验证零匹配、多匹配和选项缺失均安全停止。
4. 在真实草稿执行写入、保存、重开和独立回读；不点击最终发布。
5. 只有完整报告能够区分匹配、差异、不可读取和未覆盖后，才把相关 capability 升级为 beta。
